# Spark / GitHub Actions synchronization

Firebase Authentication (GitHub) and RTDB Rules enforce the three numeric GitHub identities. No HTTP session API is needed in Actions mode. The browser writes records and queues retries; the worker runs approximately every fifteen minutes. GitHub scheduled runs may be delayed. Cross-repository changes are polled, since issue events only trigger workflows in the repository containing the workflow.

The worker uses Google OIDC credentials through `google-github-actions/auth`. Required repository secrets: `GCP_WORKLOAD_IDENTITY_PROVIDER`, `GCP_DEPLOY_SERVICE_ACCOUNT`, and an owner-specific fine-grained GitHub token (`WORKSPACE_GH_PAT_YSSOLO`, `WORKSPACE_GH_PAT_GANDT`, or `WORKSPACE_GH_PAT_SHOTA656`) for each configured repository. GitHub reserves the `GITHUB_` prefix for Secret names; the workflow maps these Secrets to the server's existing `GITHUB_TOKEN_*` environment variables. Slack digest additionally needs `SLACK_BOT_TOKEN`. Never commit token values or service account keys. Restrict the Google workload identity trust to this repository's default branch; give the service account Firebase database access and only the deployment permissions needed.

`workspace-sync.yml` serializes runs and supports manual dispatch. Pending local changes are pushed first; clean linked records are read back from GitHub. Issue marker recovery prevents a retry from creating another Issue after an interrupted database write. A newer local edit during a push stays pending. The current worker still needs real acceptance verification for concurrent edits during a pull, milestone creation recovery, and Slack delivery after process interruption.

For the first real acceptance run, set manual input `project_id` to the existing acceptance Project ID and leave `send_digest` false. Only that Project's Milestones and Tasks are reconciled; results are recorded under `pm/acceptanceRuns/<projectId>` rather than reporting global integration health. Invalid or unknown IDs and combining a scope with a global Slack digest fail before synchronization. Leaving the input empty retains normal all-Project reconciliation. This workflow must first be enabled on the default branch; passing local tests does not prove live Issue creation or OIDC access.

The weekday 00:00 UTC schedule corresponds to 09:00 JST. Daily receipts suppress already completed digests; scheduler delays may delay delivery. Actions quotas depend on repository visibility and account plan. This is not a guarantee of free or punctual execution.
